Detailed Description

Flow-level traffic demand generation for the mesh.

TrafficMatrix maintains a list of Flow objects and updates them each tick according to the configured traffic model. There are no packets — a flow simply represents "node A wants X Mbps to node B."

Lifecycle

TrafficMatrix tm(cfg);
tm.Initialize(numNodes, 0.0); // once, before the step loop
// each tick, before routing:
tm.Tick(currentTime);
auto& flows = tm.GetActiveFlows();
auto results = router.Route(links, flows, numNodes);

Traffic models

model Flow creation Per-tick update
"constant" All flows created at Initialize. None; flows run for the full simulation.
"poisson" New flows arrive each tick via Poisson. New flows added; expired flows removed.
"on_off" All flows created at Initialize. ON/OFF state machine per flow.

Flow removal Expired flows (end_time_s > 0 and active == false) are erased from m_flows each tick. Permanent flows (end_time_s == 0) are never removed, even when they transition to inactive in the on-off model.

Gateway resolution For the "gateway" topology, TrafficConfig::gateway_node_id is resolved as a numeric index first (stoul); if that throws, it falls back to a linear search by NodeSpec::id string. Index 0 is used when gateway_node_id is empty.
