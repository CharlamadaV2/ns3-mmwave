Detailed Description

ConfigLoader: parses run.ini + referenced nodes.json / buildings.json and returns a fully populated SimConfig struct.

TopologyBuilder: creates ns-3 mobility models, buildings, and propagation models for the mesh topology. This is the only layer that creates ns-3 objects. No EPC, RRC, MAC, or protocol stack.

MeshRouter: routes flows over the mesh link graph. Supports Dijkstra shortest-path, widest-path (max throughput), and min-hop (BFS) algorithms. Applies proportional-fairness congestion scaling when links are overloaded.

VizWriter: writes per-tick CSV snapshots for GUI and plotting consumption. Called from the step loop at viz_tick_ms intervals.

RunLogger: writes a run.log capturing seeds, CLI overrides, and resolved config for reproducibility. Header-only (same pattern as progress-logger.h). No ns-3 dependency.

ProgressLogger: prints simulation progress to stderr. Called directly from the step loop (no Simulator::Schedule). Header-only.

MetricsWriter: accumulates per-tick metrics in-memory during the step loop, then writes summary.json after the simulation completes.

SINR-to-capacity mapping functions. Pure math, no ns-3 dependency. Used by LinkEvaluator and testable standalone.

LinkTable: NxN link quality matrix updated each tick. Wraps the flat output of LinkEvaluator::EvaluateAll() into a symmetric matrix with O(1) per-link lookup.

LinkEvaluator: wraps ns-3 propagation models to compute per-link path loss, SINR, and capacity. Core physics engine of mesh-sim.

Top-level simulation configuration and runtime metadata POD types. No ns-3 headers included — keeps compilation fast and allows use in post-run IO code without ns-3 linkage.

Mesh-specific configuration POD types: traffic generation and routing. No ns-3 headers included.

Per-link evaluation result POD type. One instance per ordered pair (tx, rx) per time step. No ns-3 headers included.

Config validation: checks a fully-loaded SimConfig for invalid or inconsistent values before the simulation runs. No ns-3 headers – can be tested independently.

Command-line parsing and pre-simulation setup helpers. Keeps sim.cc focused on orchestration.

No ns-3 headers included — this code can be compiled and tested independently of the ns-3 build.

No ns-3 headers – stdlib and nlohmann/json only.

Output files: positions.csv – time_s, node_id, x, y, z, node_type, active links.csv – time_s, node_a, node_b, dist_m, sinr_db, condition, condition_reason, capacity_mbps, delivered_mbps, hop_count rx-power.csv – time_s, node_a, node_b, rx_power_dbm mcs.csv – time_s, node_a, node_b, mcs_index, spectral_eff flows.csv – time_s, src, dst, demand_mbps, delivered_mbps, latency_ms, hop_count, routable routes.csv – time_s, src, dst, path, bottleneck_mbps, hop_count, routable
