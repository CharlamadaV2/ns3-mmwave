Detailed Description

Routes flows over the mesh link graph and applies congestion scaling.

Stateless between Route calls (all per-call state is local). The RoutingConfig is copied at construction and does not change.

Apply proportional-fairness congestion scaling to all results.

For each physical edge (identified by the sorted node-index pair) whose total demanded throughput exceeds its link capacity, scales every flow using that edge by capacity/total_demand. A flow traversing multiple bottleneck hops takes the minimum scaling factor across all of them via:

fr.delivered_mbps = min(fr.delivered_mbps, fr.demand_mbps * scale)

Edges where total_demand <= capacity are left unchanged.

Parameters
resultsFlow results to update in-place.
linksCurrent LinkTable (used to read link capacities).

Compute end-to-end path latency in milliseconds.

Uses a store-and-forward model summing two components per hop:

  • Propagation delay = distance_m / 3×10⁸ × 1000 ms.
  • Processing delay = 0.5 ms (fixed per hop; approximates L1/L2 processing at a mmWave small cell, consistent with the 3GPP TR 38.913 V17.0.0 §7 one-way user-plane latency target).

No transmission-delay term is included because traffic is modelled at flow granularity, not packet granularity.

Parameters
pathOrdered node indices from src to dst.
linksCurrent LinkTable (used to read per-hop distances).
Returns
Total one-way latency in milliseconds.

Dispatch to the appropriate path-finding algorithm and enforce the hop limit.

Calls FindPathShortestPath, FindPathMaxThroughput, or FindPathMinHop based on m_cfg.algorithm. If the found path exceeds m_cfg.max_hops hops (and max_hops > 0), an empty vector is returned and the flow is left unroutable. max_hops == 0 means unlimited.

Widest-path algorithm: maximises bottleneck link capacity.

Modified Dijkstra using a max-heap. For each candidate next hop, the path bandwidth is min(current_bottleneck, link_capacity); the node with the highest such value is expanded first. Edges with capacity_mbps <= 0 are skipped.

High-capacity links are preferred (lower weight). Edges with capacity_mbps <= 0 are treated as absent. Uses a min-heap for O((V+E)·log V) complexity.

Route all flows and return one FlowResult per flow.

Per-flow pipeline:

  1. Compute effective demand: 0.0 for inactive or off-phase flows.
  2. Skip path finding for zero-demand flows (marked unroutable unless src == dst).
  3. Call FindPath to select the best route under the configured algorithm and hop limit.
  4. Set delivered_mbps = demand_mbps (full demand, before scaling).
  5. Compute latency via ComputeLatency.
  6. After all flows are processed, call ApplyCongestionScaling to reduce delivered_mbps on overloaded edges.
Parameters
linksCurrent LinkTable from LinkEvaluator::EvaluateAll.
flowsActive flows from TrafficMatrix::GetActiveFlows.
numNodesTotal node count (cfg.nodes.size()); must match the dimension of links.
Returns
Vector of FlowResult, one per entry in flows, in the same order.
