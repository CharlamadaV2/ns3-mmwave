\doxysubsection{Detailed Description}
Routes flows over the mesh link graph and applies congestion scaling. 

Stateless between \mbox{\hyperlink{classmesh__sim_1_1MeshRouter_a5a1a1c0210655e515f0d9c62f592d64b}{Route}} calls (all per-\/call state is local). The \mbox{\hyperlink{structmesh__sim_1_1RoutingConfig}{Routing\+Config}} is copied at construction and does not change.

Apply proportional-\/fairness congestion scaling to all results. 

For each physical edge (identified by the sorted node-\/index pair) whose total demanded throughput exceeds its link capacity, scales every flow using that edge by {\ttfamily capacity/total\+\_\+demand}. A flow traversing multiple bottleneck hops takes the minimum scaling factor across all of them via\+: 
\begin{DoxyCode}{0}
\DoxyCodeLine{fr.delivered\_mbps = min(fr.delivered\_mbps, fr.demand\_mbps * scale)}

\end{DoxyCode}
 Edges where {\ttfamily total\+\_\+demand} $<$= capacity are left unchanged.

Compute end-\/to-\/end path latency in milliseconds. 

Uses a store-\/and-\/forward model summing two components per hop\+:
\begin{DoxyItemize}
\item {\bfseries{Propagation delay}} = {\ttfamily distance\+\_\+m} / 3×10⁸ × 1000 ms.
\item {\bfseries{Processing delay}} = 0.\+5 ms (fixed per hop; approximates L1/\+L2 processing at a mm\+Wave small cell, consistent with the 3GPP TR 38.\+913 V17.\+0.\+0 §7 one-\/way user-\/plane latency target).
\end{DoxyItemize}

No transmission-\/delay term is included because traffic is modelled at flow granularity, not packet granularity.

Widest-\/path algorithm\+: maximises bottleneck link capacity. 

Modified Dijkstra using a max-\/heap. For each candidate next hop, the path bandwidth is {\ttfamily min(current\+\_\+bottleneck, link\+\_\+capacity)}; the node with the highest such value is expanded first. Edges with {\ttfamily capacity\+\_\+mbps} $<$= 0 are skipped.

Route all flows and return one \mbox{\hyperlink{structmesh__sim_1_1FlowResult}{Flow\+Result}} per flow. 

{\bfseries{Per-\/flow pipeline\+:}}
\begin{DoxyEnumerate}
\item Compute effective demand\+: {\ttfamily 0.\+0} for inactive or off-\/phase flows.
\item Skip path finding for zero-\/demand flows (marked unroutable unless {\ttfamily src} == {\ttfamily dst}).
\item Call \mbox{\hyperlink{classmesh__sim_1_1MeshRouter_ace88b4e00f0ffd0f0ed17ac50a08eea0}{Find\+Path}} to select the best route under the configured algorithm and hop limit.
\item Set {\ttfamily delivered\+\_\+mbps} = {\ttfamily demand\+\_\+mbps} (full demand, before scaling).
\item Compute latency via \mbox{\hyperlink{classmesh__sim_1_1MeshRouter_a3d2a1bfd61e967a3c5e758ee05a6bb5c}{Compute\+Latency}}.
\item After all flows are processed, call \mbox{\hyperlink{classmesh__sim_1_1MeshRouter_a9079dc8eeab809bb799ff3c92b88565c}{Apply\+Congestion\+Scaling}} to reduce {\ttfamily delivered\+\_\+mbps} on overloaded edges.
