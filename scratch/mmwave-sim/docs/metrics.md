# Output Files Reference

All output files are written to `<output_dir>/` for each simulation run.
When using `run_sim.py`, the path is printed to stderr at the start of the run.

**Acronyms used in this document:**
- **DL** — Downlink (base station to user equipment)
- **UL** — Uplink (user equipment to base station)
- **eNB** (evolved Node B) — the 5G/LTE base station
- **UE** (User Equipment) — any mobile endpoint (phone, drone, vehicle, etc.)
- **SINR** (Signal-to-Interference-plus-Noise Ratio) — the key channel quality metric; higher is better
- **MCS** (Modulation and Coding Scheme) — selected automatically by AMC
- **AMC** (Adaptive Modulation and Coding) — ns3-mmwave scheduler feature that picks MCS based on SINR
- **TB** (Transport Block) — the unit of data exchanged between PHY layers
- **HARQ** (Hybrid Automatic Repeat reQuest) — retransmission mechanism; `rv > 0` means retransmit
- **BLER** (Block Error Rate) — fraction of TBs received in error
- **RNTI** (Radio Network Temporary Identifier) — UE identifier within a cell, assigned at RRC attach
- **IMSI** (International Mobile Subscriber Identity) — global UE identifier; assigned 1,2,3,… in nodes.json order
- **LCID** (Logical Channel ID) — identifies a bearer within a UE's RRC connection
- **PDU** (Protocol Data Unit) — a packet at a given protocol layer
- **RLC** (Radio Link Control) — ns-3 layer below PDCP; handles segmentation and ARQ
- **PDCP** (Packet Data Convergence Protocol) — ns-3 layer above RLC; closest to the application
- **PHY** — Physical layer
- **RRC** (Radio Resource Control) — control-plane protocol; handles attach, measurement reports, handover
- **EPC** (Evolved Packet Core) — the core network; PGW is its gateway to the internet
- **LOS** (Line of Sight) — unobstructed direct path between transmitter and receiver
- **NLOS** (Non-Line of Sight) — path obstructed by a building or other obstacle

## Trace Files Generated by ns-3

These files are written directly by ns-3 trace sinks during the simulation.
They are plain-text, typically tab-separated.  All timestamps are in seconds.

---

### RxPacketTrace.txt

**Generator:** `MmWavePhyTrace`
**When:** One row per transport block (TB) attempted by the PHY layer.
**Format:** Tab-separated; first row is the header.

| Column | Name | Description |
|---|---|---|
| 0 | `DL/UL` | Direction: `DL` = downlink (eNB→UE), `UL` = uplink (UE→eNB) |
| 1 | `time` | Simulation time at reception (seconds) |
| 2 | `frame` | Frame number |
| 3 | `subF` | Subframe number |
| 4 | `slot` | Slot number |
| 5 | `1stSym` | First OFDM (Orthogonal Frequency Division Multiplexing) symbol in the allocation |
| 6 | `symbol#` | Number of allocated OFDM symbols |
| 7 | `cellId` | Cell (eNB) identifier |
| 8 | `rnti` | UE Radio Network Temporary Identifier (RNTI) |
| 9 | `ccId` | Component carrier ID |
| 10 | `tbSize` | Transport block (TB) size in bytes |
| 11 | `mcs` | Modulation and Coding Scheme (MCS) index (0–28; higher = higher throughput) |
| 12 | `rv` | Redundancy version: 0 = first HARQ transmission; 1–3 = retransmissions |
| 13 | `SINR(dB)` | **Effective SINR over this transport block** — from the simulation (see note) |
| 14 | `corrupt` | 1 if the TB was received with errors, 0 if successfully decoded |
| 15 | `TBler` | TB error rate estimate at the receiver |

---

### DlRlcStats.txt / UlRlcStats.txt

**Generator:** `MmWaveBearerStatsCalculator`
**When:** One row per IMSI/LCID pair per epoch (default epoch: 0.25 s).
**Format:** Tab-separated; lines starting with `%` are headers/comments.

| Column | Name | Description |
|---|---|---|
| 0 | `start` | Epoch start time (seconds) |
| 1 | `end` | Epoch end time (seconds) |
| 2 | `CellId` | Cell identifier |
| 3 | `IMSI` | UE International Mobile Subscriber Identity (IMSI) — 1-indexed, in nodes.json order |
| 4 | `RNTI` | UE Radio Network Temporary Identifier (RNTI) |
| 5 | `LCID` | Logical Channel ID (LCID) |
| 6 | `nTxPDUs` | Number of Protocol Data Units (PDUs) transmitted |
| 7 | `TxBytes` | Bytes transmitted |
| 8 | `nRxPDUs` | Number of PDUs received |
| 9 | `RxBytes` | Bytes received |
| 10 | `delay` | Mean PDU delay in this epoch (seconds) |
| 11 | `stdDev` | Standard deviation of PDU delay |
| 12 | `min` | Minimum PDU delay |
| 13 | `max` | Maximum PDU delay |
| 14 | `PduSize` | Mean PDU size (bytes) |
| 15 | `stdDev` | PDU size std dev |
| 16 | `min` | Min PDU size |
| 17 | `max` | Max PDU size |

**IMSI → node ID mapping:** UE nodes are assigned IMSI values starting at 1
in the order they appear in `nodes.json`. First UE = IMSI 1, second = IMSI 2.
eNB nodes are skipped in IMSI numbering.

**Throughput calculation:**
```
throughput_mbps = RxBytes * 8 / (end - start) / 1e6
```
For total run throughput, sum `RxBytes` across all non-warmup epochs for a
given IMSI, then divide by total measurement time.

---

### DlPdcpStats.txt / UlPdcpStats.txt

**Generator:** `MmWaveBearerStatsCalculator`
**When:** One row per IMSI/LCID per epoch, at the Packet Data Convergence Protocol (PDCP) layer.
**Format:** Same column layout as DlRlcStats.txt / UlRlcStats.txt.

PDCP sits above Radio Link Control (RLC) in the protocol stack.  PDCP stats
reflect application-level PDU delivery; RLC stats reflect radio link-level
delivery including ARQ retransmissions.  For most analyses, the RLC stats are
more informative.

---

### DlPhyTransmissionTrace.txt / UlPhyTransmissionTrace.txt

**Generator:** `MmWavePhyTrace`
**When:** One row per PHY transmission event (eNB side for DL, UE side for UL).
**Format:** Tab-separated.

| Column | Name | Description |
|---|---|---|
| 0 | `time` | Simulation time (seconds) |
| 1 | `cellId` | Cell identifier |
| 2 | `rnti` | UE RNTI |
| 3 | `ccId` | Component carrier |
| 4 | `numSym` | Number of OFDM symbols used |
| 5 | `tbSize` | Transport block size in bytes |
| 6 | `mcs` | MCS index selected by AMC |
| 7 | `rank` | MIMO (Multiple Input Multiple Output) rank |
| 8 | `sinr` | SINR used for MCS selection (dB) — from simulation |

This file records the **transmitter-side** view.  Pair with RxPacketTrace.txt
(receiver-side) to understand HARQ retransmissions (`rv > 0` in RxPacketTrace).

---

### MmWaveSinrTime.txt

**Generator:** `MmWaveBearerStatsConnector`
**When:** One row per SINR measurement event (driven by the PHY report period).
**Format:** Tab-separated.

| Column | Name | Description |
|---|---|---|
| 0 | `time` | Measurement time (seconds) |
| 1 | `imsi` | UE IMSI |
| 2 | `cellId` | Cell identifier |
| 3 | `sinr` | Wideband SINR (dB) — from the RRC measurement report |

This is a SINR time series sourced directly from the simulation's RRC layer.
Useful for:
- Plotting SINR vs. time for a moving UE
- Detecting outage durations (how long SINR stayed below a threshold)
- Comparing channel conditions between seeds

---

### EnbSchedAllocTraces.txt

**Generator:** `MmWaveMacTrace`
**When:** One row per scheduler allocation decision.
**Format:** Tab-separated.

| Column | Name | Description |
|---|---|---|
| 0 | `time` | Scheduling slot time (seconds) |
| 1 | `cellId` | Cell identifier |
| 2 | `rnti` | UE RNTI receiving this allocation |
| 3 | `numSym` | Number of symbols allocated to this UE in this slot |
| 4 | `tbSize` | Transport block size scheduled (bytes) |
| 5 | `mcs` | MCS index for this allocation |

Useful for understanding how the scheduler distributes resources across UEs.
High-load scenarios may show starvation (some UEs getting zero allocations in
some slots).

---

### stderr.txt

**Generator:** ns-3 logging system
**When:** Written continuously during the simulation run.

Captures all ns-3 `NS_LOG_*` output including:
- INFO messages from MmWaveSim (config load, topology build, progress)
- Any warnings from the channel or mobility models
- Error messages if something fails

Check this file first when debugging unexpected results.

## Files Generated by mmwave-sim

---

### positions.csv

**Generator:** `VizWriter` (periodic tick, every `viz_tick_ms` ms)
**Purpose:** Node position snapshots for visualisation tools.

Metadata header lines (prefix `#`):
```
# scenario=<name>
# frequency=<Hz>
# txPower=<dBm>
# numNodes=<N>
# simDuration=<ms>
# tickMs=<ms>
# dimensions=3   (coordinates always stored as x,y,z triples)
```

Data columns:
| Column | Name | Description |
|---|---|---|
| 0 | `time_s` | Snapshot time (seconds) |
| 1 | `node_id` | ns-3 node integer ID |
| 2 | `x` | X coordinate (metres) |
| 3 | `y` | Y coordinate (metres) |
| 4 | `z` | Z coordinate (metres) |
| 5 | `node_type` | `"bs"` (base station), `"ground"` (UE z ≤ 5 m), `"air"` (UE z > 5 m) |
| 6 | `active` | Always `1` in current implementation |

**Coordinate note:** Positions are always stored as 3D (x, y, z) triples
regardless of scenario dimensionality.  For 2D scenarios set z to a constant
height.  For 1D scenarios set y = 0 and z to a constant height.

---

### links.csv

**Generator:** `VizWriter` (same tick as positions.csv)
**Purpose:** Per-link channel state snapshots for visualisation.

| Column | Name | Description |
|---|---|---|
| 0 | `time_s` | Snapshot time (seconds) |
| 1 | `node_a` | eNB node ID |
| 2 | `node_b` | UE node ID |
| 3 | `dist_m` | 3D Euclidean distance between the two nodes (metres) |
| 4 | `sinr_db` | SINR (dB) from the simulation's RRC measurement report — see note |
| 5 | `condition` | `"LOS"` or `"NLOS"` from `BuildingsChannelConditionModel` |

**Note on sinr_db:** This is the actual SINR reported by the RRC layer
(`LteEnbRrc/NotifyMmWaveSinr` trace), the same measurement the scheduler uses
to select MCS.  It reflects the full simulation channel including shadow fading,
beam tracking, and the `ThreeGppChannelModel`.  The value is `-999` for ticks
that fire before the first RRC measurement report arrives (typically the first
100–200 ms while UEs complete RRC attach).

---

### summary.json

**Generator:** `MetricsWriter` (written once, after `Simulator::Run()` completes)
**Purpose:** Computed per-UE and network-level metrics, ready for programmatic use.

```json
{
  "scenario": "single-enb-3ue",
  "seed": 42,
  "run_id": 1,
  "duration_s": 2.0,
  "warmup_s": 0.1,
  "node_positions": {
    "enb0": [0.0, 0.0, 10.0],
    "ue0": [60.0, -30.0, 1.6]
  },
  "per_ue": {
    "ue0": {
      "mean_sinr_db": 15.3,
      "min_sinr_db": 8.1,
      "outage_fraction": 0.02,
      "corruption_rate": 0.01,
      "dl_throughput_mbps": 142.3,
      "dl_delay_mean_ms": 1.2
    }
  },
  "network": {
    "mean_sinr_db": 13.5,
    "min_sinr_db": -8.4,
    "outage_fraction": 0.04,
    "sum_dl_throughput_mbps": 466.5
  }
}
```

### Field definitions

All SINR values come from `RxPacketTrace.txt`, which contains the actual
per-TB SINR computed by the ns-3 PHY layer.

| Field | Description |
|---|---|
| `per_ue.<id>.mean_sinr_db` | Mean SINR (dB) across all DL TBs for this UE after warmup |
| `per_ue.<id>.min_sinr_db` | Minimum SINR (dB) across all non-warmup DL TBs |
| `per_ue.<id>.outage_fraction` | Fraction of DL TBs with SINR < −5 dB (hardcoded analysis threshold, does not affect simulation) |
| `per_ue.<id>.corruption_rate` | Fraction of DL TBs received with errors (`corrupt=1`) — proxy for BLER |
| `per_ue.<id>.dl_throughput_mbps` | DL throughput in Mbps (total RxBytes / measurement duration) |
| `per_ue.<id>.dl_delay_mean_ms` | Mean per-PDU DL delay in milliseconds |
| `network.mean_sinr_db` | Mean of per-UE mean SINRs |
| `network.min_sinr_db` | Minimum SINR across all UEs and all TBs |
| `network.outage_fraction` | Fraction of all DL TBs (across all UEs) below −5 dB |
| `network.sum_dl_throughput_mbps` | Sum of per-UE DL throughput |

`null` values indicate no data was available (e.g., trace file was empty or
UE had no packets after warmup).

## pcap/ subdirectory

**Created when:** `pcap_enabled = true` in `[output]` of `run.ini`.
**Contents:** `.pcap` (packet capture) files from `PointToPointHelper::EnablePcapAll()`
on the backhaul link (Evolved Packet Core (EPC) PGW ↔ remote host).

Files are named `backhaul-<device_index>-<node_id>.pcap`.
Open with Wireshark or `tcpdump -r <file>`.

The backhaul captures DL UDP traffic from the remote host to the EPC, and
UL traffic from the EPC to the remote host.  This is application-level
traffic before it enters the mmWave radio link.

---

## aggregated_summary.json

**Generator:** `run_sweep.py` after all seeds complete.
**Purpose:** Mean ± std for each metric across seeds.

```json
{
  "num_seeds": 5,
  "seeds": [1, 2, 3, 4, 5],
  "network": {
    "mean_sinr_db": {"mean": 13.5, "std": 0.8, "n": 5},
    "sum_dl_throughput_mbps": {"mean": 466.5, "std": 12.3, "n": 5}
  },
  "per_ue": {
    "ue0": {
      "mean_sinr_db": {"mean": 15.3, "std": 1.1, "n": 5}
    }
  }
}
```

Each seed runs as a completely separate process with its own output directory,
so there is no shared in-memory state between seeds.  Metrics from one seed
cannot contaminate another.  The aggregation reads independent `summary.json`
files and computes statistics over them.
